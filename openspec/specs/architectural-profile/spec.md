# architectural-profile

## Purpose

Архитектурный профиль как предмет: из каких измерений он собирается, какие значения в них
допустимы, какие сочетания существуют и что происходит с недопустимым или неупорядоченным набором.
Способ задать профиль — опрос — добавляется последующим изменением цепочки.

## Requirements

### Requirement: Профиль собирается из четырёх независимых измерений

Профиль SHALL состоять ровно из четырёх измерений: язык, тип проекта, архитектура, паттерны.
Язык, тип проекта и архитектура MUST принимать ровно одно значение; паттерны MUST принимать
набор значений, в том числе пустой. Измерения независимы: значение одного измерения не ограничивает
значения остальных.

#### Scenario: Профиль с одним значением в каждом обязательном измерении

- **WHEN** заданы язык, тип проекта, архитектура и пустой набор паттернов
- **THEN** профиль создан и описывает проект полностью

#### Scenario: Профиль с несколькими паттернами

- **WHEN** в измерении паттернов заданы оба допустимых значения
- **THEN** профиль создан и содержит оба значения

### Requirement: Значения измерений записываются kebab-case латиницей

Каждое значение измерения SHALL быть строкой kebab-case латиницей. Одна и та же строка MUST служить
именем значения везде, где оно встречается: в пункте опроса, в поле манифеста и в имени накладки.
Допустимые значения: язык — `go`, `python`; тип проекта — `monolith`, `modular-monolith`, `service`,
`distributed`; архитектура — `clean-architecture`, `ports-adapters`, `layered`; паттерны — `ddd`,
`cqrs`.

#### Scenario: Имя значения совпадает во всех употреблениях

- **WHEN** значение измерения прочитано из профиля
- **THEN** это та же строка, которой значение названо в словаре, без преобразования регистра
  и разделителей

### Requirement: Допустимы все сочетания значений

Все сочетания допустимых значений SHALL быть допустимыми профилями — 96 сочетаний. Перечень всех
допустимых профилей MUST быть доступен как единый список: по нему работает приёмочный прогон,
и его размер MUST равняться 96.

#### Scenario: Перечень допустимых профилей полон

- **WHEN** запрошен перечень допустимых профилей
- **THEN** в нём 96 элементов, и каждое сочетание значений встречается ровно один раз

#### Scenario: Сочетание с пустым набором паттернов входит в перечень

- **WHEN** в перечне отыскивается профиль без паттернов
- **THEN** такой профиль в перечне есть для каждого сочетания остальных трёх измерений

### Requirement: Недопустимое значение отклоняется при создании профиля

Создание профиля со значением, которого нет в словаре соответствующего измерения, SHALL
завершаться отказом с ошибкой, называющей измерение и отвергнутое значение. Профиль
с недопустимым значением MUST быть невозможен: проверка выполняется при создании, а не при
использовании.

#### Scenario: Неизвестное значение обязательного измерения

- **WHEN** профиль создаётся со значением языка, которого нет в словаре
- **THEN** создание завершается ошибкой, называющей измерение и отвергнутое значение, и профиль
  не создан

#### Scenario: Неизвестное значение в наборе паттернов

- **WHEN** в наборе паттернов есть значение, которого нет в словаре
- **THEN** создание завершается ошибкой, и профиль не создан

### Requirement: Набор паттернов нормализован

Набор паттернов профиля SHALL быть нормализован при создании: повторы значений MUST быть сняты,
порядок значений MUST быть приведён к порядку применения — `ddd`, затем `cqrs`. Два профиля,
заданные одинаковыми значениями в разном порядке или с повторами, MUST быть равны между собой.

#### Scenario: Повтор значения в наборе паттернов

- **WHEN** профиль создаётся с набором паттернов, где значение повторено
- **THEN** профиль создан, и в его наборе паттернов это значение одно

#### Scenario: Порядок значений не влияет на профиль

- **WHEN** два профиля созданы одинаковыми значениями, но паттерны перечислены в разном порядке
- **THEN** профили равны, и порядок их паттернов — `ddd`, затем `cqrs`
