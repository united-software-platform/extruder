# acceptance-run

## Purpose

Приёмочный прогон: как профили отбираются для проверки, какие свойства проверяются у каждого
сгенерированного проекта и что прогон предъявляет разработчику. Прогон — проверка самого Extruder,
а не часть поставляемого инструмента.

## Requirements

### Requirement: Профили берутся из словаря и отбираются фильтром реализованных значений

Прогон SHALL брать профили из перечня допустимых профилей, а не составлять их собственной
комбинаторикой. Отбор SHALL выполняться фильтром реализованных значений: профиль берётся в прогон
тогда и только тогда, когда реализованы его язык, тип проекта, архитектура и каждое значение
из его набора паттернов. Пустой набор паттернов требований к фильтру MUST не предъявлять.

#### Scenario: Профиль со всеми реализованными значениями взят

- **WHEN** в фильтре отмечены язык, тип проекта и архитектура профиля, а его набор паттернов пуст
- **THEN** профиль взят в прогон

#### Scenario: Профиль с нереализованным паттерном не взят

- **WHEN** все обязательные измерения профиля реализованы, но одно из значений его набора паттернов
  в фильтре не отмечено
- **THEN** профиль в прогон не взят

#### Scenario: Пустой фильтр

- **WHEN** фильтр не содержит ни одного реализованного значения
- **THEN** ни один профиль не взят, и прогон завершается успешно

### Requirement: Каждый взятый профиль проверяется тремя свойствами

Для каждого взятого профиля прогон SHALL вызвать точку входа генератора и затем проверить три
свойства сгенерированного проекта: проект собирается, его тест проходит, линтер чист. Свойства
MUST проверяться вызовом целей `build`, `test` и `lint` оснастки самого сгенерированного проекта:
прогон не знает ни языка профиля, ни инструментов этого языка. Свойство считается выполненным,
если вызванная цель завершилась успешно.

#### Scenario: Все три свойства выполнены

- **WHEN** генератор отработал без ошибки и все три цели оснастки завершились успешно
- **THEN** профиль получает вердикт «прошёл»

#### Scenario: Цель оснастки завершилась ошибкой

- **WHEN** одна из трёх целей завершилась ошибкой
- **THEN** профиль получает вердикт «не прошёл», и вывод упавшей цели предъявлен

#### Scenario: Оснастка не содержит нужной цели

- **WHEN** в сгенерированном проекте нет одной из трёх целей
- **THEN** профиль получает вердикт «не прошёл» с причиной «цель отсутствует», отличимой от провала
  самой цели

#### Scenario: Генератор завершился ошибкой

- **WHEN** точка входа генератора вернула ошибку
- **THEN** профиль получает вердикт «не прошёл» с причиной «отказ генератора», свойства
  не проверяются

### Requirement: Прогон предъявляет охват и вердикты

Прогон SHALL печатать число взятых профилей вместе с общим числом допустимых — в виде «взято N
профилей из 96», — вердикт по каждому взятому профилю с его значениями и итоговую сводку числа
прошедших и упавших. Число взятых профилей MUST печататься и тогда, когда оно равно нулю:
по нему читается охват проверки на текущем этапе работ.

#### Scenario: Прогон при пустом фильтре

- **WHEN** прогон выполнен с пустым фильтром
- **THEN** напечатано «взято 0 профилей из 96», и прогон завершается кодом `0`

#### Scenario: Прогон с частично заполненным фильтром

- **WHEN** фильтр отмечает часть значений
- **THEN** напечатано число взятых профилей из 96, вердикт по каждому из них и сводка прошедших
  и упавших

### Requirement: Падение профиля не останавливает прогон

Прогон SHALL проверять все взятые профили независимо от результата предыдущих: первое падение
MUST не прекращать прогон. Итоговый вердикт прогона — неуспех, если хотя бы один профиль
не прошёл.

#### Scenario: Один профиль из нескольких упал

- **WHEN** взято несколько профилей и один из них не прошёл
- **THEN** остальные профили проверены, сводка содержит и прошедшие, и упавшие, а прогон
  завершается неуспехом

### Requirement: Дерево упавшего профиля сохраняется

Сгенерированные проекты SHALL записываться в отдельный каталог на профиль внутри служебного
каталога прогона, игнорируемого системой контроля версий. Каталог профиля, прошедшего все три
свойства, MUST удаляться; каталог упавшего профиля MUST оставаться для разбора. Служебный каталог
прогона MUST очищаться в начале прогона, чтобы деревья предыдущего прогона не смешивались
с текущими.

#### Scenario: Профиль прошёл

- **WHEN** профиль прошёл все три свойства
- **THEN** его каталог удалён

#### Scenario: Профиль упал

- **WHEN** профиль не прошёл
- **THEN** его каталог со сгенерированным деревом остался на месте и назван в вердикте

#### Scenario: Повторный прогон

- **WHEN** прогон запущен повторно
- **THEN** деревья предыдущего прогона удалены до первой генерации

### Requirement: Прогон запускается отдельно от обычных тестов

Приёмочный прогон SHALL запускаться отдельной командой и MUST не выполняться в составе обычного
прогона тестов проекта: его время измеряется минутами и растёт с числом реализованных значений.
Команда запуска MUST быть доступна из контейнера агента через раннер хоста.

#### Scenario: Обычный прогон тестов

- **WHEN** выполнен обычный прогон тестов проекта
- **THEN** приёмочный прогон не выполнялся

#### Scenario: Запуск из контейнера агента

- **WHEN** агент запрашивает цель приёмочного прогона у раннера хоста
- **THEN** прогон выполняется на хосте, и его вывод возвращается агенту
