## 1. Роль теста-заготовки

- [ ] 1.1 Добавить роль теста-заготовки в перечень ролей `plan/domain` в конец объявления, не в середину; проверка — тест перечня опознаёт новую роль, а существующие роли сохраняют прежние имена
- [ ] 1.2 Внести роль в вкладчик типа проекта как роль уровня проекта по [решению 5](./design.md#решение-5-тест-заготовка--роль-уровня-проекта); проверка — для типа «сервис» роли уровня проекта содержат манифест модуля, точку входа, цель сборки и тест-заготовку
- [ ] 1.3 Обновить строковый эталон плана первого среза в тесте печати; проверка — сценарий дельта-спеки [`structure-plan`](./specs/structure-plan/spec.md) «Роли уровня проекта вне слоёв» подтверждён тестом, тест-заготовка предъявлена на верхнем уровне

## 2. Дерево файлов и контракты

- [ ] 2.1 Создать раскладку модуля `internal/render/{domain,app,infra}` по [решению 1](./design.md#решение-1-модуль-internalrender-и-выбор-бэкенда-в-точке-сборки); проверка — каталоги существуют, `internal/plan` и `internal/profile` на `internal/render` не ссылаются
- [ ] 2.2 Объявить в `render/domain` дерево файлов как `fs.FS` поверх карты по [решению 2](./design.md#решение-2-отрендеренное-дерево--fsfs-поверх-карты): узел несёт относительный путь и содержимое; проверка — тест обходит дерево `fs.WalkDir` и читает содержимое каждого файла, путь с выходом за корень деревом не принимается
- [ ] 2.3 Объявить в `render/app` контракт бэкенда рендеринга: принимает план и имя проекта, возвращает дерево; проверка — контракт не содержит ни путей целевого языка, ни обращений к файловой системе, подмена реализации в тесте возможна
- [ ] 2.4 Объявить в `render/app` контракт каталога назначения (перечень столкновений и запись дерева) и контракт утверждения; проверка — оба подменяются в тесте, а сценарий создания структуры компилируется без пакета `os`
- [ ] 2.5 Зафиксировать в комментарии `render/app`, почему контракт назначения не разделён на чтение и запись по [CQRS](../../../rules/cqrs.md#принадлежность-контрактов-слоям): дерево не агрегат, контракт — порт файловой системы; проверка — пояснение присутствует и называет причину, а не факт

## 3. Бэкенд рендеринга Go

- [ ] 3.1 Реализовать в `render/infra` правило путей по таблице [решения 4](./design.md#решение-4-правило-путей-бэкенда-go); проверка — сценарии спеки [`rendering-backend`](./specs/rendering-backend/spec.md) «Слои разделены в дереве» и «Роли уровня проекта вне каталогов слоёв» подтверждены тестами
- [ ] 3.2 Реализовать шаблоны ролей на `text/template` строками в коде по [решению 3](./design.md#решение-3-шаблоны--texttemplate-строками-в-коде): подстановки — имя модуля и путь импорта; проверка — сценарий «Ни один файл дерева не пуст» подтверждён тестом, `embed` в change не появляется
- [ ] 3.3 Написать заготовки ролей слоёв — сущность, контракт репозитория, сценарий использования, реализация репозитория, входящий обработчик — минимальным валидным кодом на стандартной библиотеке по [решению 6](./design.md#решение-6-заготовки-написаны-под-линтер-по-умолчанию); проверка — идентификаторы экспортируемые, ошибки обработаны, внешних зависимостей нет
- [ ] 3.4 Написать заготовки ролей уровня проекта: `go.mod`, `Makefile` с целями `build`, `lint`, `test`, точку входа со связкой слоёв и тест-заготовку, проверяющий эту связку; проверка — секции целей `Makefile` укладываются в норму [MAKE-001](../../../rules/makefile-rules.md#норма-объёма-секции-make-001), тест-заготовка выполняет хотя бы одну проверку
- [ ] 3.5 Вывести имя модуля из имени каталога назначения с приведением к допустимому виду и отказом при непригодном имени; проверка — сценарии «Имя взято из каталога» и «Непригодное имя каталога отвергается» подтверждены тестами
- [ ] 3.6 Отвергать роль, для которой у бэкенда нет ни пути, ни шаблона; проверка — сценарий «Роль без поддержки в переводе отвергается» подтверждён тестом, сообщение называет роль
- [ ] 3.7 Зафиксировать golden-эталон дерева первого вертикального среза: состав путей и содержимое каждого файла; проверка — сценарии «Все роли плана отрендерены», «Имя элемента совпадает с его ролью» и «Сравнение с эталоном без диска» подтверждены тестами, обращения к диску в тестах нет
- [ ] 3.8 Подтвердить детерминированность перевода; проверка — сценарии «Повторный перевод даёт то же дерево» и «Смена каталога меняет только имя модуля» подтверждены тестами

## 4. Сценарий создания структуры

- [ ] 4.1 Реализовать в `render/app` сценарий создания структуры в порядке [решения 9](./design.md#решение-9-всё-или-ничего-в-пределах-предсказуемых-причин): рендеринг → проверка столкновений → утверждение → запись → итог; каталог назначения приходит параметром по [решению 8](./design.md#решение-8-каталог-назначения--параметр-сценария-а-не-процессное-состояние); проверка — порядок шагов виден в тесте на подменённых контрактах, рабочий каталог процесса сценарий не читает
- [ ] 4.2 Реализовать проверку столкновений по всему дереву до первой записи; проверка — сценарии спеки [`write-approval`](./specs/write-approval/spec.md) «Столкновение отвергает всю запись», «Соседство без столкновения допустимо» и «Проверка идёт до первой записи» подтверждены тестами
- [ ] 4.3 Реализовать запись дерева в `render/infra` через `os`: каталоги создаются по путям узлов, существующие файлы не открываются на запись; проверка — тест во временном каталоге получает дерево, совпадающее с golden-эталоном по составу и содержимому
- [ ] 4.4 Реализовать спрашивающее утверждение в `render/infra`: вопрос в поток ошибок, ответ со стандартного ввода, подтверждающие значения `y` и `yes` без учёта регистра, всё прочее — отказ по [решению 7](./design.md#решение-7-утверждение-интерактивность-приходит-параметром); проверка — сценарии «Подтверждение открывает запись», «Отказ оставляет каталог нетронутым» и «Разделение потоков» подтверждены тестами
- [ ] 4.5 Предъявить итог записи: сообщение о создании структуры и число созданных файлов в стандартный поток вывода; проверка — сценарий «Итог после записи» подтверждён тестом, число совпадает с числом файлов в каталоге
- [ ] 4.6 Сообщать о промежуточном состоянии каталога при отказе файловой системы посреди записи; проверка — тест с контрактом назначения, отказывающим на середине дерева, получает сообщение с числом созданных файлов и ненулевой код возврата

## 5. Точка сборки и точка входа

- [ ] 5.1 Добавить в точку сборки выбор бэкенда по измерению «язык» и отказ для языка без бэкенда; проверка — сценарии «Язык определяет дерево» и «Язык без перевода отвергается до записи» подтверждены тестами, файловая система при отказе не изменяется
- [ ] 5.2 Расширить запуск точки сборки стандартным вводом и признаком интерактивности, вычисляемым в `cmd/extruder` по `os.Stdin`; проверка — тест подставляет оба параметра, точка входа передаёт реальные значения
- [ ] 5.3 Добавить флаг подтверждения `--yes` и его описание в справку; проверка — сценарии «Запись без вопроса» и «Поток ввода не читается» подтверждены тестами, справка называет флаг
- [ ] 5.4 Реализовать отказ при неинтерактивном вводе без флага подтверждения; проверка — сценарии «Неинтерактивный вызов без флага» и «Неинтерактивный вызов с флагом» подтверждены тестами, сообщение называет флаг
- [ ] 5.5 Отвергать позиционные аргументы: каталог назначения аргументом не задаётся; проверка — сценарии «Позиционный аргумент отвергается» и «Дерево появляется в текущем каталоге» подтверждены тестами
- [ ] 5.6 Сохранить неизменность файловой системы при отказе разбора и при выдаче справки; проверка — сценарии дельта-спеки [`profile-input`](./specs/profile-input/spec.md) «Отказ разбора не касается диска» и «Справка не касается диска» подтверждены тестами
- [ ] 5.7 Сверить, что действующие требования `profile-input` и `structure-plan` не нарушены; проверка — существующие тесты обоих модулей проходят, из ожиданий правится только эталон плана из задачи 1.3

## 6. Проверка и завершение

- [ ] 6.1 Написать приёмочный тест по [решению 10](./design.md#решение-10-два-рода-тестов-дерево-в-памяти-тулчейн-во-временном-каталоге): генерация во временный каталог и прямой вызов `go build`, `golangci-lint run`, `go test`; проверка — сценарии «Сборка проходит», «Линтер молчит» и «Тесты-заготовки проходят» подтверждены, тест пропускается с явной причиной при отсутствии тулчейна
- [ ] 6.2 Прогнать `make build`, `make lint`, `make test` через раннер; проверка — все три цели завершаются успешно, приёмочный тест в прогоне выполняется, а не пропускается
- [ ] 6.3 Проверить инструмент вручную во временном каталоге: с подтверждением, с отказом, с `--yes`, при занятом имени; проверка — поведение совпадает со спекой `write-approval` в каждом из четырёх вызовов
- [ ] 6.4 Сверить покрытие: каждый сценарий дельта-спек `rendering-backend`, `write-approval`, `profile-input` и `structure-plan` имеет соответствующий тест; проверка — непокрытых сценариев не осталось, а оставленные открытыми названы с причиной
- [x] 6.5 Внести ревизию [плана разработки](../../../docs/project-plan.md): границу «первая версия пишет в пустой каталог» привести к решению «отказ только при столкновении имён», сохранив «чужое дерево не разбирает»; проверка — раздел «Границы первой версии» согласован с дельта-спекой `write-approval`, запись внесена в таблицу версий и в журнал приёмки после решения пользователя
- [ ] 6.6 Прогнать `openspec validate render-plan-to-filesystem --strict`; проверка — валидация проходит без ошибок
- [ ] 6.7 Синхронизировать спеки в инвентарь; проверка — `openspec list --specs` показывает `rendering-backend` и `write-approval` рядом с `profile-input` и `structure-plan`, а изменённые требования обеих действующих возможностей обновлены
