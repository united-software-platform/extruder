## 1. Окружение сборки

- [x] 1.1 Добавить в `.env.example` переменные образа тулчейна Go (имя и тег) по [DOCK-009](../../../rules/docker.md#переменные-окружения-dock-004-dock-009-dock-010); проверка — переменные присутствуют с несекретными умолчаниями, `.env` не трогается
- [x] 1.2 Добавить в `docker-compose.yml` сервис `extruder-build` по [`rules/docker.md`](../../../rules/docker.md): префикс имени, совпадающий `container_name`, явная сеть, значения из `.env` без `env_file`, `restart: "no"`, непривилегированный пользователь, портов не публикует; проверка — `docker compose config` разбирает файл без ошибок, отступления действующего сервиса `claude` не тиражированы
- [x] 1.3 Добавить в `Makefile` цели `build`, `lint`, `test`, запускающие тулчейн в сервисе `extruder-build`; проверка — каждая цель укладывается в 30 строк по [MAKE-001](../../../rules/makefile-rules.md#норма-объёма-секции-make-001), цели видны в выводе `make help`
- [x] 1.4 Прогнать `sh tools/make-lint/check.sh` после правки `Makefile` по [MAKE-004](../../../rules/makefile-rules.md#локальный-прогон-проверки-make-004); проверка — код возврата `0`
- [x] 1.5 Добавить `build`, `lint`, `test` в `ALLOWED_TARGETS` файла [`runner.py`](../../../tools/host-runner/runner.py); проверка — `tools/host-runner/call.sh build` доходит до раннера, а имя вне списка по-прежнему отклоняется кодом `400`
- [x] 1.6 Зафиксировать расхождение с поставкой kit'а: перечислить в [`docs/project-context.md`](../../../docs/project-context.md) правленые файлы `docker-compose.yml`, `Makefile`, `tools/host-runner/runner.py`; проверка — раздел «Состав поставки kit'а» называет расхождение и его причину, таблица версий документа дополнена строкой

## 2. Каркас модуля Go

- [x] 2.1 Создать манифест модуля Go с путём `github.com/united-software-platform/extruder`; проверка — `make build` доходит до компиляции, а не падает на отсутствии манифеста
- [x] 2.2 Создать раскладку каталогов по [решению 2](./design.md#decisions): `cmd/extruder/`, `internal/profile/{domain,app,infra}/`; проверка — каталоги существуют, направление зависимостей соответствует [CLAR-001](../../../rules/clean-architecture.md#слои-и-направление-зависимостей-clar-001)
- [x] 2.3 Создать точку входа, печатающую справку и завершающуюся ненулевым кодом без аргументов; проверка — `make build` собирает бинарник, запуск без аргументов даёт ненулевой код возврата
- [x] 2.4 Добавить конфигурацию линтера Go и включить её в цель `lint`; проверка — `make lint` завершается без замечаний на текущем коде
- [x] 2.5 Дополнить `.gitignore` артефактами сборки Go; проверка — `git status` чист после `make build`

## 3. Домен профиля

- [x] 3.1 Реализовать измерения «язык», «тип проекта», «архитектура» как объекты-значения с проверкой значения в конструкторе по [DDD-014](../../../rules/ddd.md#value-object-ddd-012014); проверка — тест подтверждает, что недопустимое значение объект не создаёт
- [x] 3.2 Реализовать измерение «подходы и паттерны» как набор объектов-значений, допускающий пустоту и отвергающий повтор; проверка — тесты на пустой набор, на два значения и на повторённое значение проходят
- [x] 3.3 Объявить перечни допустимых значений в домене единственной точкой определения по [решению 6](./design.md#decisions), составом первого вертикального среза по [решению 7](./design.md#decisions); проверка — перечень объявлен один раз, справка и сообщение об ошибке читают его оттуда
- [x] 3.4 Реализовать профиль как объект-значение из четырёх измерений без идентичности; проверка — тест подтверждает, что два профиля с одинаковыми значениями равны

## 4. Ввод профиля

- [x] 4.1 Реализовать сценарий разбора профиля в слое приложения: входной контракт — сырые значения измерений, выходной — разобранный профиль, одна публичная операция по [CLAR-008](../../../rules/clean-architecture.md#слой-приложения-clar-007013); проверка — тест сценария проходит без обращения к командной строке
- [x] 4.2 Собрать все ошибки ввода, а не первую: недостающие обязательные измерения перечисляются вместе; проверка — сценарий спеки «Не указано несколько обязательных измерений» подтверждён тестом
- [x] 4.3 Сформировать сообщение об отказе из трёх частей — измерение, полученное значение, перечень допустимых; проверка — сценарий спеки «Неизвестное значение языка» подтверждён тестом
- [x] 4.4 Реализовать обработчик команды на `spf13/cobra` в `internal/profile/infra/`, флаги `--language`, `--project-type`, `--architecture`, `--patterns` по [решению 5](./design.md#decisions); проверка — домен и слой приложения не импортируют `cobra` ([CLAR-016](../../../rules/clean-architecture.md#слой-инфраструктуры-clar-014016))
- [x] 4.5 Развести потоки вывода: разобранный профиль — в стандартный поток вывода, диагностика — в поток ошибок; проверка — оба сценария требования «Разобранный профиль предъявляется в стандартный поток вывода» подтверждены тестами
- [x] 4.6 Наполнить справку перечнем измерений с их обязательностью и допустимыми значениями из домена; проверка — сценарии спеки «Запрос справки» и «Вызов без аргументов» подтверждены тестами

## 5. Проверка и завершение

- [x] 5.1 Подтвердить тестом, что инструмент не изменяет файловую систему ни при успехе, ни при отказе; проверка — состав временного рабочего каталога до и после вызова совпадает
- [x] 5.2 Сверить покрытие: каждый сценарий [`specs/profile-input/spec.md`](./specs/profile-input/spec.md) имеет соответствующий тест; проверка — непокрытых сценариев не осталось
- [x] 5.3 Прогнать `make build`, `make lint`, `make test` из контейнера агента через раннер; проверка — все три цели завершаются успешно, критерий готовности этапа выполнен
- [x] 5.4 Прогнать `openspec validate bootstrap-extruder-cli --strict`; проверка — валидация проходит без ошибок
- [x] 5.5 Синхронизировать спеку в инвентарь: `openspec/specs/profile-input/spec.md`; проверка — `openspec list --specs` показывает возможность `profile-input`
