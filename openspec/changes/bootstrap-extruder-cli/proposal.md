# Предложение: каркас Extruder и ввод профиля из командной строки

Обоснование и границы change `bootstrap-extruder-cli` — этапа 0–1
[карты плана](../../../docs/project-plan.md#карта-changeей): окружение сборки, каркас модуля Go
и первая наблюдаемая функция — разбор профиля из аргументов командной строки.

## Why

План разработки принят, но кода в репозитории по-прежнему нет: ни модуля Go, ни точки входа,
ни окружения, в котором проект собирается и проверяется. Пока их нет, ни один следующий этап
карты стартовать не может — плану структуры этапа 2 не на чём расти.

Ограничение окружения делает задачу шире, чем «создать модуль»: в контейнере агента нет ни Go,
ни `make`, ни `docker`, а белый список раннера целей ограничен `init`, `openspec-init` и `help`.
Критерий готовности этапа — «сборка и линтер чисты» — в таком окружении непроверяем, поэтому
окружение сборки создаётся тем же change, что и код.

## What Changes

- **Окружение сборки.** В `docker-compose.yml` добавляется сервис с тулчейном Go; в `Makefile` —
  цели сборки, линтера и тестов; в белый список [`runner.py`](../../../tools/host-runner/runner.py)
  добавляются новые цели, чтобы агент запускал их из контейнера.
- **Каркас модуля Go.** Манифест модуля, точка входа, раскладка каталогов по
  [CLAR-022](../../../rules/clean-architecture.md#модульная-организация-clar-022023), конфигурация
  линтера, записи в `.gitignore` для артефактов сборки.
- **Модель профиля.** Четыре измерения как объекты-значения с проверкой инвариантов при создании
  ([DDD-012](../../../rules/ddd.md#value-object-ddd-012014)); профиль — объект-значение, собранный
  из них. Перечень допустимых значений на этом этапе живёт в коде.
- **Ввод профиля из командной строки.** Профиль задаётся флагами по измерениям; разобранный
  профиль печатается в стандартный вывод. Ошибочное значение отвергается сообщением, называющим
  измерение, недопустимое значение и перечень допустимых.
- **На диск не пишет.** Ни файла, ни каталога change не создаёт: запись появляется на этапе 3.

Ломающих изменений нет: ломать нечего — публичного поведения у проекта пока не было.

## Capabilities

### New Capabilities

- `profile-input`: задание архитектурного профиля на входе Extruder — синтаксис флагов по
  измерениям, проверка значений по перечню допустимых, предъявление разобранного профиля
  и отказ с указанием причины.

### Modified Capabilities

Изменённых возможностей нет: инвентарь `openspec/specs/` пуст, менять нечего.

## Impact

- **Новые файлы проекта** — манифест и исходники модуля Go, конфигурация линтера. Манифестом
  kit'а не покрыты.
- **Файлы поставки kit'а затрагиваются осознанно** — `docker-compose.yml`, `Makefile`
  и `tools/host-runner/runner.py`. Это расхождение с `.sdd-kit-manifest.json`, которое придётся
  разрешать вручную при переустановке kit'а; иначе критерий готовности этапа непроверяем.
- **Внешняя зависимость** — `spf13/cobra` для разбора командной строки; первая зависимость
  проекта.
- **Следующий этап** — `add-structure-plan` (этап 2): строит план структуры из модели профиля,
  созданной здесь.
- **Спецификации** — появляется первая: `openspec/specs/profile-input/spec.md` после синхронизации.
