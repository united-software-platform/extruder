# Задачи: план структуры

Перечень работ change `add-structure-plan`: контракт между фазами, построение плана из профиля,
предъявление плана и проверка независимости от языка.

## 1. Контракт

- [ ] 1.1 Создать раскладку модуля `internal/plan/{domain,app,infra}` по [решению 3](./design.md#decisions); проверка — каталоги существуют, `internal/profile` на `internal/plan` не ссылается
- [ ] 1.2 Объявить в `plan/domain` перечень ролей закрытым типом и перечень видов слоёв, единственной точкой определения по образцу `profile/domain`; проверка — тест подтверждает, что значение вне перечня не опознаётся, а перечень объявлен один раз
- [ ] 1.3 Объявить узлы контракта: `Plan` с модулями и ролями уровня проекта, `Module` со слоями, `Layer` с видом и ролями по [решению 1](./design.md#decisions); проверка — роли уровня проекта лежат отдельным полем, а не псевдослоем; тест собирает план вручную и читает все три уровня

## 2. Вкладчики измерений

- [ ] 2.1 Вкладчик типа проекта: число модулей и роли уровня проекта — манифест модуля, точка входа, цель сборки, входящий обработчик; проверка — для типа «сервис» возвращается один модуль, сценарий спеки «Тип проекта «сервис» даёт один модуль» подтверждён тестом
- [ ] 2.2 Вкладчик архитектуры: слои модуля и базовые роли внутри них; проверка — для `layered` возвращаются слои домена, приложения и инфраструктуры, сценарий спеки «Архитектура задаёт слои» подтверждён тестом
- [ ] 2.3 Вкладчик паттернов: дополнительные роли в существующих слоях; проверка — для пустого набора паттернов вклад пуст, сценарий спеки «Профиль без паттернов даёт только базовые роли» подтверждён тестом
- [ ] 2.4 Зафиксировать порядок узлов объявлением вкладчиков без перебора ассоциативных массивов по [решению 6](./design.md#decisions); проверка — тест прогоняет построение подряд и получает одинаковый порядок узлов

## 3. Построение плана

- [ ] 3.1 Реализовать сценарий построения плана в `plan/app`: принимает тип проекта, архитектуру и паттерны, **но не профиль целиком** по [решению 2](./design.md#decisions); проверка — сигнатура не содержит профиля и языка, `plan/` нигде не импортирует `Language`
- [ ] 3.2 Собрать в сценарии состав первого среза по [решению 5](./design.md#decisions): слой домена — `entity` и `repository-contract`, слой приложения — `use-case`, слой инфраструктуры — `repository-impl` и `inbound-handler`, роли проекта — манифест, точка входа, цель сборки; проверка — тест сравнивает построенный план с эталонной структурой
- [ ] 3.3 Подтвердить детерминированность построения; проверка — сценарий спеки «Повторный вызов даёт тот же вывод» подтверждён тестом на уровне структуры

## 4. Предъявление плана

- [ ] 4.1 Реализовать печать плана деревом с символами ветвления в `plan/infra` по [решению 7](./design.md#decisions); проверка — иерархия «модуль → слои → роли» видна в выводе, сценарий спеки «Иерархия видна в выводе» подтверждён тестом
- [ ] 4.2 Предъявить роли уровня проекта на верхнем уровне вывода, вне слоёв; проверка — сценарий спеки «Роли уровня проекта вне слоёв» подтверждён тестом
- [ ] 4.3 Подключить построение и печать к обработчику команды модуля `profile`: план идёт в стандартный поток вывода после профиля, без флага; проверка — сценарии спеки «План следует за профилем» и «План печатается без дополнительных флагов» подтверждены тестами
- [ ] 4.4 Убедиться, что при отказе разбора план не печатается и поток вывода остаётся пустым; проверка — сценарий спеки «При отказе разбора план не печатается» подтверждён тестом
- [ ] 4.5 Сверить, что действующие требования `profile-input` не нарушены; проверка — все 27 существующих тестов проходят без правки ожиданий

## 5. Проверка и завершение

- [ ] 5.1 Зафиксировать строковый эталон плана первого вертикального среза в тесте; проверка — эталон сравнивается посимвольно, обращения к файловой системе в тесте нет
- [ ] 5.2 Тест независимости от языка: два профиля, различающиеся только языком, дают совпадающий вывод; проверка — сценарий спеки «Смена языка не меняет план» подтверждён тестом
- [ ] 5.3 Тест отсутствия языковых признаков по [решению 8](./design.md#decisions): в напечатанном плане нет расширений, разделителей пути и объявлений пакета; проверка — сценарии спеки «В выводе нет расширений и путей» и «Узел не несёт содержимого» подтверждены тестами
- [ ] 5.4 Сверить покрытие: каждый сценарий [`specs/structure-plan/spec.md`](./specs/structure-plan/spec.md) имеет соответствующий тест; проверка — непокрытых сценариев не осталось
- [ ] 5.5 Прогнать `make build`, `make lint`, `make test` через раннер; проверка — все три цели завершаются успешно
- [ ] 5.6 Прогнать `openspec validate add-structure-plan --strict`; проверка — валидация проходит без ошибок
- [ ] 5.7 Синхронизировать спеку в инвентарь; проверка — `openspec list --specs` показывает `structure-plan` рядом с `profile-input`
