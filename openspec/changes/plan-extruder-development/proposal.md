# Предложение: зафиксировать план разработки Extruder

Обоснование и границы change `plan-extruder-development`: создание документа плана разработки
Extruder как карты последующих change'ей и введение процедуры его приёмки.

## Why

Кода приложения в репозитории нет, а объём задачи Extruder велик: профиль собирается из четырёх
независимых измерений, и наивная реализация «шаблон на комбинацию» даёт произведение вариантов
вместо суммы. Без зафиксированного плана первый же change разрастается до неуправляемого объёма —
его нельзя ни принять, ни отклонить целиком, — а последующие изменения теряют общий порядок.

План обязан жить **вне** артефактов change: содержимое `openspec/changes/archive/` не читается
никогда ([READ-004](../../../rules/reading-rules.md#запрет-каталогов-read-004)), поэтому план,
положенный в `proposal.md`, станет недоступен агенту сразу после архивации этого change — в тот
момент, когда он нужнее всего.

## What Changes

- Создаётся `docs/project-plan.md` — единственный носитель плана разработки Extruder.
- В плане фиксируются:
  - **технологическое решение** — реализация на Go с обоснованием выбора;
  - **модель решения** — двухфазное преобразование «профиль → абстрактный план структуры →
    дерево на диске», в котором язык подключается только на последнем шаге;
  - **определение готовности** сгенерированной структуры: проект собирается, линтер целевого
    языка молчит, тесты-заготовки проходят, дерево совпадает с эталоном;
  - **карта change'ей** — перечень последующих изменений с границами и критерием готовности
    каждого, по одному на этап.
- Вводится раздел «Журнал приёмки» документа плана: решение пользователя, причина отказа и
  ответная доработка фиксируются построчно; причина отказа записывается **до** начала доработки.
- Критерий завершения change — явная приёмка плана пользователем. Отказ не завершает change:
  причина фиксируется, план дорабатывается и предъявляется снова, число итераций не ограничено.

Кода в рамках этого change не появляется: ни исходников, ни манифестов сборки, ни конфигурации
инструментов целевого языка.

## Capabilities

### New Capabilities

Новых возможностей продукта change не вводит.

### Modified Capabilities

Изменённых возможностей нет: инвентарь `openspec/specs/` пуст, требований к поведению Extruder
change не затрагивает.

Change изменяет только документацию проекта, поэтому в `.openspec.yaml` установлен
`skip_specs: true`. Дельта-спеки для процессного change были бы выдуманными: спецификация
описывает поведение продукта, а поведение здесь не меняется.

---

## Impact

- **Новый файл** — `docs/project-plan.md`; файл проекта, `.sdd-kit-manifest.json` его не покрывает.
- **Файлы поставки kit'а не затрагиваются**: `CLAUDE.md`, `AGENTS.md`, `Makefile`,
  `docker-compose.yml`, `.env.example`, содержимое `rules/` и `tools/` остаются без изменений.
- **Последующие change'и** создаются по карте плана — по одному, после его приёмки. В рамках этого
  change они не создаются.
- **Зависимостей, API и кода** изменение не касается: их в репозитории нет.
