# Extruder

Extruder превращает архитектурный профиль приложения в его начальную структуру: по выбранному
языку, типу проекта, архитектуре и набору паттернов инструмент формирует начальную структуру
проекта, соответствующую профилю.

## Архитектурный профиль

Профиль собирается из четырёх измерений:

- **язык** — Go, PHP, Python и другие;
- **тип проекта** — монолит, модульный монолит, сервис, распределённая система;
- **архитектура** — Clean Architecture, Ports & Adapters, Layered Architecture и другие;
- **паттерны** — Domain-Driven Design (DDD), Command Query Responsibility
  Segregation (CQRS) и другие.

Измерения независимы: значение одного не ограничивает выбор в остальных. Результат —
начальная структура проекта, отвечающая выбранному профилю.

## Окружение разработки

Проект ведётся в окружении SDD Developer Kit: правила разработки лежат в каталоге
[`rules/`](./rules), точка подключения правил в контекст агента — [`CLAUDE.md`](./CLAUDE.md).

Подготовка окружения и перечень команд:

```bash
make init
make help
```

## Требования к хосту

Сборка, тесты и линтер Extruder выполняются на хосте: в контейнере агента нет ни `make`,
ни Go. На хосте нужен Go 1.27 или новее — по умолчанию цели ищут его в `/usr/local/go/bin`.

Линтер ставится целью проекта, отдельной установки не требует:

```bash
make go-tools
```

Цель кладёт `golangci-lint` версии `GOLANGCI_VERSION` в `$(HOME)/go/bin`. Если инструменты
установлены иначе, каталоги переопределяются переменными `GO_BIN_DIR` и `GO_TOOLS_DIR`:

```bash
make GO_BIN_DIR=/opt/go/bin go-build
```
