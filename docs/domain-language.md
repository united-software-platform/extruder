# Единый язык Extruder

Канонические имена понятий предметной области Extruder: как понятие называется, что оно означает
и какие слова для него не используются. Источник имён для кода, документов и интерфейса опроса.

## Как читать документ

Единый язык (Ubiquitous Language) — общий словарь команды и кода: имена типов, функций и пунктов
интерфейса совпадают с именами из этого документа
([DDD-001](../rules/ddd.md#единый-язык-ddd-001002)).

Каждая запись даёт каноническое имя в формате
[TERM-004](../rules/terminology.md#ввод-аббревиатуры-в-тексте), определение и строку
`Избегать` — слова, которые обозначают то же понятие и потому запрещены
([TERM-002](../rules/terminology.md#каноническое-имя-и-аббревиатура)).

Документ — словарь и только словарь: решений он не принимает и деталей реализации не содержит.
Решения живут в [`extruder-design.md`](./extruder-design.md), порядок работ —
в [`project-plan.md`](./project-plan.md).

## Профиль

**Архитектурный профиль (Architectural Profile)**
Сочетание значений четырёх измерений, полностью определяющее начальную структуру проекта.
Допустимо называть просто профилем после первого упоминания.
`Избегать`: сочетание, конфигурация, шаблон, пресет.

**Измерение (Dimension)**
Независимая ось профиля. Измерений четыре: язык, тип проекта, архитектура, паттерны.
`Избегать`: параметр, ось, критерий, категория.

**Значение измерения (Dimension Value)**
Одна допустимая строка измерения, записанная kebab-case латиницей. Одна и та же строка служит
пунктом опроса, полем манифеста и именем накладки.
`Избегать`: опция, вариант, флаг.

**Паттерны (Patterns)**
Единственное измерение с множественным выбором; пустой набор допустим.
`Избегать`: подходы и паттерны, практики, методологии.

## Опрос

**Опрос (Survey)**
Интерактивная последовательность вопросов — единственный способ задать профиль.
`Избегать`: диалог, анкета, визард, интервью.

**Идентификатор проекта (Project Identifier)**
Имя, под которым проект известен системе сборки выбранного языка: путь go-модуля в Go, имя
дистрибутива в Python. Единственный параметр, который опрос собирает помимо профиля.
`Избегать`: имя модуля, путь модуля, имя приложения.

**Сводка (Summary)**
Последний экран опроса, показывающий профиль и выведенный из него план генерации целиком;
последняя точка отказа перед записью.
`Избегать`: подтверждение, итог, превью.

## Генерация

**Накладка (Overlay)**
Объявление шагов плана, которым одно значение измерения вносит свой вклад. Файлов накладка
не пишет и путей не занимает: она объявляет, что должно измениться в модели проекта.
`Избегать`: шаблон, слой, патч, плагин, генератор.

**Шаг плана (Plan Step)**
Единица плана генерации: одно изменение модели проекта, объявленное накладкой. Шаг адресует
предмет модели, а не путь файла. Накладка шаги объявляет — выполняется шаг.
`Избегать`: операция, команда, действие, правка файла.

**План генерации (Generation Plan)**
Предложенная будущая модель проекта: состав шагов и дерево путей, включая оснастку, выведенные
из профиля и версии Extruder. Текстов файлов не содержит; предъявляется в сводке и утверждается
пользователем.
`Избегать`: сценарий генерации, программа генерации, журнал сборки. Планом не называется порядок
реализации самого Extruder — он живёт в [`project-plan.md`](./project-plan.md).

**Модель проекта (Project Model)**
Полное описание проекта, которое меняют шаги плана: язык, тип проекта, архитектура, паттерны,
модули, слои, предметы, контракты. То, что утверждено и реализовано; носитель — манифест. Текст
файлов получается рендером модели один раз, в конце.
`Избегать`: состояние, схема, слепок, представление. Моделью не называется план: план —
предложение, модель — факт.

**Точка входа генератора (Generator Entry Point)**
Единственная операция, которой вызывающая сторона запускает генерацию начальной структуры проекта
по заданному профилю. Контракт объявляет приёмочный прогон, заполняют — изменения Ядра.
`Избегать`: API генератора, фасад, интерфейс генерации, сценарий генерации.

**Раскладка (Layout)**
Правило размещения файлов и каталогов, которое задаёт значение измерения, — например раскладка Go.
`Избегать`: раскладкой не называются ни результат генерации, ни этап работ над ним.

**Сквозной пример (End-to-End Example)**
Одна законченная операция от обработчика до хранения с репозиторием в памяти, входящая
в начальную структуру проекта.
`Избегать`: базовый пример, демо, sample, заглушка.

## Результат

**Начальная структура проекта (Initial Project Structure)**
То, что Extruder записывает в целевой каталог по заданному профилю: дерево каталогов, файл
сборки, конфигурация линтера, сквозной пример, тест, `README.md` и манифест.
`Избегать`: выход, заготовка, скелет, каркас, boilerplate. Слово «дерево» не называет результат
целиком, но остаётся в словосочетаниях о его частях — «дерево каталогов», «базовое дерево».

**Файл сборки (Build File)**
Файл, которым система сборки языка описывает проект: `go.mod` в Go, `pyproject.toml` в Python.
`Избегать`: манифест сборки, файл зависимостей.

**Модуль (Module)**
Доменный модуль начальной структуры проекта: самостоятельная граница контекста со своими слоями
([CLAR-023](../rules/clean-architecture.md#модульная-организация-clar-022023)).
`Избегать`: словом «модуль» не называется путь go-модуля — это понятие языка Go, а не Extruder.

## Каталоги

**Каталог пользователя (User Directory)**
Каталог на хосте, который пользователь монтирует в целевой каталог при запуске контейнера.
`Избегать`: каталог хоста, рабочий каталог.

**Целевой каталог (Target Directory)**
Фиксированная точка монтирования внутри контейнера, куда записывается начальная структура
проекта. Путь задан образом и не вводится пользователем.
`Избегать`: точка монтирования как самостоятельный термин, выходной каталог, каталог назначения.

**Временный каталог (Staging Directory)**
Каталог внутри целевого, куда идёт запись до полного успеха и откуда содержимое переносится
на место.
`Избегать`: буфер, временная папка, temp.

## Манифест и повторный запуск

**Манифест (Manifest)**
Файл `.extruder.yaml` в начальной структуре проекта: сериализованная модель проекта вместе
с версией формата, версией Extruder, датой и sha256 каждого сгенерированного файла. Манифест —
носитель модели, а не её замена.
`Избегать`: манифест сборки, слепок, лок-файл, состояние.

**Повторный запуск (Re-run)**
Запуск Extruder в каталоге, где манифест уже есть: опрос спрашивает только паттерны, существующие
пути плана перечисляются предупреждением, генерация выполняется полностью.
`Избегать`: перегенерация, обновление, апгрейд, синхронизация.

## Приёмочный прогон

**Приёмочный прогон (Acceptance Run)**
Проверка самого Extruder: каждый отобранный профиль генерируется, и у сгенерированного проекта
проверяются три свойства — проект собирается, его тест проходит, линтер чист. В поставляемый
инструмент не входит и запускается отдельно от обычного прогона тестов.
`Избегать`: приёмочный тест, интеграционный тест, e2e-прогон, smoke-тест.

**Фильтр реализованных значений (Implemented Values Filter)**
Перечень значений измерений, накладки которых генератор уже умеет применять. Им приёмочный прогон
отбирает профили из перечня допустимых: профиль берётся, когда реализованы его язык, тип проекта,
архитектура и каждое значение набора паттернов.
`Избегать`: белый список, список поддержанных профилей, покрытие.

**Свойство (Property)**
Проверяемое утверждение о сгенерированном проекте, а не об ожидаемом содержимом его файлов.
Свойств три: проект собирается, его тест проходит, линтер чист.
`Избегать`: критерий, проверка, ассерт. Свойством не называется цель оснастки — цель лишь способ
проверить свойство.

> **Примечание:** приёмочный прогон — контекст проверки самого Extruder, а не предметной области
> инструмента. Поэтому «итоговая сводка прогона» и «Сводка» опроса — одно слово в двух разных
> контекстах ([DDD-004](../rules/ddd.md#ограниченный-контекст-ddd-003005)); в тексте о прогоне
> слово «сводка» употребляется только с уточнением «прогона».

## Понятия из других документов

Понятие определяется один раз — в том документе, который его вводит
([TERM-001](../rules/terminology.md#единый-источник-определения)). Здесь такие понятия
не переопределяются:

- Решение (Design Decision, DEC) — [`extruder-design.md`](./extruder-design.md#как-читать-документ);
- слой, сценарий использования, контракт репозитория — [`clean-architecture.md`](../rules/clean-architecture.md);
- агрегат, сущность, объект-значение, доменное событие — [`ddd.md`](../rules/ddd.md);
- контракт чтения и контракт записи — [`cqrs.md`](../rules/cqrs.md).
