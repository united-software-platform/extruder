# Решения по устройству Extruder v1

Свод решений, принятых при проектировании Extruder: профиль, опрос, конвейер генерации, состав
выхода, манифест, устройство самого инструмента и границы первой версии. Документ — источник
для формирования изменений OpenSpec; порядок работ — в [`project-plan.md`](./project-plan.md).

## Как читать документ

Решение (Design Decision, DEC) — зафиксированный выбор с обоснованием, принятый в сессии
проектирования. Идентификатор — `DEC-NNN` по
[TERM-008](../rules/terminology.md#коды-сущностей). Далее по тексту — только DEC.

Каждое DEC — предмет реализации: изменение OpenSpec ссылается на конкретные номера, а не
пересказывает их. Отменить DEC можно новой записью в таблице версий, но не молчаливым
отступлением при реализации.

## Профиль

**[DEC-001]** Измерения независимы: значение одного не ограничивает выбор в остальных, матрицы
совместимости нет. Отсюда 2 × 4 × 3 × 4 = 96 допустимых сочетаний, и каждое обязано давать
работающий результат.

**[DEC-002]** Множественный выбор допустим только у паттернов. Два языка в одном выходе — другой
продукт: он поднимает вопросы о границе между языковыми частями, на которые профиль не отвечает.
Две архитектуры несовместимы по существу: `clean-architecture` и `layered` предписывают
противоположные направления зависимостей
([CLAR-001](../rules/clean-architecture.md#слои-и-направление-зависимостей-clar-001)).

**[DEC-003]** Одна и та же строка используется в трёх местах: пункт опроса, поле манифеста, имя
накладки. Расхождение между ними запрещает [TERM-008](../rules/terminology.md#коды-сущностей).

| Измерение | Значения |
|-----------|----------|
| Язык | `go`, `python` |
| Тип проекта | `monolith`, `modular-monolith`, `service`, `distributed` |
| Архитектура | `clean-architecture`, `ports-adapters`, `layered` |
| Паттерны | `ddd`, `cqrs` |

## Опрос

**[DEC-004]** Профиль задаётся только через диалог. Флаги, файл профиля и переменные окружения
как способ ввода не предусмотрены: это сознательное сужение первой версии.

**[DEC-005]** Порядок: язык, тип проекта, архитектура, паттерны, имя модуля, сводка. Сначала
профиль — то, ради чего инструмент запущен; имя модуля — параметр, а не архитектурное решение.
Сводка показывает всё, что произойдёт, и является последней точкой отказа.

**[DEC-006]** Путь модуля нельзя ни вывести, ни угадать: для Go он обычно содержит хост
и владельца. Умолчанием подставляется имя целевого каталога.

**[DEC-007]** Без терминала опрос либо виснет, либо падает на первом же вопросе. Проверка
выполняется на старте, сообщение называет правильную команду запуска.

**[DEC-008]** Русский интерфейс соответствует [DOC-001](../rules/documentation-rules.md#язык-и-терминология);
имена значений остаются латиницей по [DOC-002](../rules/documentation-rules.md#язык-и-терминология).

## Целевой каталог и запись

**[DEC-009]** Пользователь монтирует свой каталог в фиксированную точку. Ввод пути открывал бы
возможность указать несмонтированный каталог — и записать результат внутрь контейнера, где он
исчезнет вместе с ним.

**[DEC-010]** Пустота проверяется без учёта служебных каталогов: типичный сценарий — `git init`
в новом каталоге перед запуском, и отказ из-за `.git` выглядел бы дефектом. При конфликтах
показывается список файлов и задаётся один вопрос: поштучный опрос на десятках файлов приводит
к бездумному согласию.

**[DEC-011]** Временный каталог располагается **внутри целевого**: перенос между файловыми
системами не атомарен, а целевой каталог смонтирован с хоста.

**[DEC-012]** Образ на `scratch` не имеет оболочки, поэтому диагностика прав возможна только
сообщением самого Extruder. Проверка выполняется до первого вопроса, чтобы отказ не пришёл после
заполненного опроса.

## Конвейер генерации

**[DEC-013]** Композиция вместо шаблона на сочетание: добавление языка должно быть линейной
работой, а не умножением числа шаблонов. Поздняя накладка перезаписывает файл ранней — паттерны
уточняют то, что задала архитектура.

**[DEC-014]** `cqrs` применяется после `ddd`, потому что содержательно надстраивается над ним:
разделяет надвое уже существующее понятие репозитория
([CQRS-001](../rules/cqrs.md#подробное-описание), [DDD-020](../rules/ddd.md#repository-ddd-020022)).
Порядок фиксирован в декларациях, а не зависит от порядка ответов: иначе два пользователя
с одинаковым профилем получили бы разные проекты.

**[DEC-015]** Вшитые накладки означают, что раскладка однозначно определяется версией
инструмента. Цена: до следующей версии пользователь не может добавить свой язык или паттерн
иначе как правкой репозитория Extruder.

**[DEC-016]** Профиль без паттернов даёт тот же сквозной пример в упрощённом виде: сущность без
объектов-значений и событий, один репозиторий, один сценарий. Иначе базовый профиль выдавал бы
пустые каталоги — результат хуже, чем у выбравшего галочку.

## Состав выхода

**[DEC-017]** Минимально настроенный проект без инфраструктуры:

| Файл | Go | Python |
|------|----|--------|
| Манифест сборки | `go.mod` | `pyproject.toml` (`uv`) |
| Цели сборки | `Makefile`: `build`, `test`, `lint` | те же имена целей |
| Линтер | `.golangci.yml` | `ruff` в `pyproject.toml` |
| Тесты | `_test.go` рядом с кодом | каталог `tests/` |

Имена целей `Makefile` намеренно совпадают для обоих языков: это единственный интерфейс, который
пользователь видит одинаковым независимо от профиля.

**[DEC-018]** Сквозной пример — одна законченная операция от обработчика до хранения, с
репозиторием в памяти: он компилируется и проходит тест без базы данных, то есть без
инфраструктуры. Пример лежит одним каталогом, чтобы удаляться одним действием.

**[DEC-019]** `README.md` — единственное место, где человек прочтёт, что означает дерево и какой
командой его собрать. `LICENSE` не создаётся: выбор лицензии не архитектурное решение, спросить
о нём негде, а подстановка по умолчанию навязала бы юридическое решение.

## Раскладки

**[DEC-020]** Верхний уровень разбиения доменный, слои внутри модуля —
[CLAR-022](../rules/clean-architecture.md#модульная-организация-clar-022023). `internal/`,
а не `pkg/`: сгенерированный проект — заготовка приложения, а не публичная библиотека.

**[DEC-021]** src-layout устраняет типичную ошибку, когда тесты импортируют код из рабочего
каталога, а не из установленного пакета. Буквальный перенос структуры Go отвергнут: Extruder
обещает идиоматичную заготовку, а не транслитерацию.

**[DEC-022]** `layered` раскладывается настоящими слоями верхнего уровня — иначе значение
сохраняет имя, но теряет смысл. Формально это противоречит
[CLAR-022](../rules/clean-architecture.md#модульная-организация-clar-022023), поэтому
в документации Extruder фиксируется явно: `rules/` — норма для самого инструмента, а не для его
выхода.

**[DEC-023]** Два модуля — минимум, на котором видна межмодульная граница и запрет обращаться
к внутренностям соседа ([CLAR-023](../rules/clean-architecture.md#модульная-организация-clar-022023),
[DDD-005](../rules/ddd.md#ограниченный-контекст-ddd-003005)). При одном модуле `monolith`
и `modular-monolith` дали бы почти одинаковое дерево.

**[DEC-024]** Оркестрация — то, что отличает распределённую систему от сервиса, поэтому её вносит
накладка типа проекта. `docker-compose.yaml` обязан сразу соответствовать
[DOCK-001](../rules/docker.md#префикс-имён-dock-001002)..[DOCK-015](../rules/docker.md#сервис-инициализации-состояния-dock-014-dock-015):
префиксы имён, обязательная сеть, `container_name`, запрет `env_file`, `.env.example` рядом.

## Манифест и повторный запуск

**[DEC-025]** Контрольные суммы нужны, чтобы отличить нетронутый файл от правленного вручную.
Версия формата отделена от версии инструмента: формат меняется редко, инструмент часто, и склейка
ломала бы чтение старых манифестов при каждом релизе.

**[DEC-026]** Повторный запуск добавляет недостающее и никогда не трогает изменённое. Без
контрольных сумм это неотличимо от полной перегенерации: генератор не знал бы, что чужое.

**[DEC-027]** Наложение `layered` на `clean-architecture` оставило бы в дереве обе структуры
разом, притом собираться оно, скорее всего, продолжило бы — то есть дефект был бы молчаливым.
Смена архитектуры — новый проект в новом каталоге, и так и сообщается пользователю.

## Устройство Extruder

**[DEC-028]** Инструмент строится по тем же правилам, которые генерирует: расхождение между
проповедуемым и собственным устройством — самый заметный дефект такого проекта. Bootstrap
отвергнут: он поставил бы генератор в зависимость от собственной незрелой версии.

**[DEC-029]** Сеть инструменту не нужна вовсе — он работает и при `--network none`. Следствия
`scratch`: сборка многоступенчатая, пользователь задаётся числовым uid, внутрь образа не зайти,
поэтому диагностика держится на сообщениях самого Extruder
([DOCK-012](../rules/docker.md#пользователь-контейнера-приложения-dock-012-dock-013)).

## Проверки и поставка

**[DEC-030]** Прогон по свойствам: каждое из 96 сочетаний собирается, его тест проходит, линтер
чист. Golden-снимки содержимого отвергнуты — они перекрашиваются при любой правке шаблона.

**[DEC-031]** Разделение по событию: проверки на каждое изменение, публикация только по тегу,
который ставит релизный сценарий. Так опубликованный образ однозначно соответствует версии,
и невозможен образ из случайного коммита.

**[DEC-032]** Механизм уже описан в
[GIT-021](../rules/git-rules.md#исключение-для-машинного-релизного-коммита): релизный сценарий
меняет файл версии и создаёт коммит `Релиз vX.Y.Z`.

**[DEC-033]** Осознанное расхождение с поставкой: правятся `Makefile` и
`tools/host-runner/runner.py`, оба перечислены в `.sdd-kit-manifest.json`. Основание: Go
в контейнере агента нет, сборка возможна только на хосте через раннер, а раннер запускает
`make <цель>` в корне репозитория. Расхождение фиксируется в изменении «поставка», а не вносится
попутно.

## Границы первой версии

> **Важно:** перечисленное исключено сознательно и не является упущением.

- SDD Developer Kit в любом виде — ни в поставке выхода, ни скачиванием, ни секцией опроса;
- флаги и файл профиля как альтернатива опросу;
- внешний каталог накладок и пользовательские расширения;
- полиязычные проекты и множественный выбор архитектуры;
- английский интерфейс и механизм локализации;
- `Dockerfile`, `docker-compose.yaml` и конфигурация CI в выходе — кроме профиля `distributed`;
- `LICENSE` в выходе;
- публикация образа в реестр до готового приёмочного прогона.

## Открытые вопросы

**Обнаружение молчаливой потери файла.** Накладка, применённая позже, может затереть файл ранней;
вместе с файлом исчезает и относящийся к нему тест, поэтому прогон по свойствам
([DEC-030](#проверки-и-поставка)) остаётся зелёным на неполной раскладке. Рассмотренные варианты:
объявленный в накладке список обязательных путей с проверкой после применения всех накладок;
счётчик повторных записей с предупреждением; осознанное принятие риска. Решение перенесено
в изменение «ядро» и должно быть принято до того, как накладок станет больше двух.
