## Назначение

Extruder превращает архитектурный профиль приложения в его начальную структуру. Профиль
собирается из четырёх независимых измерений — язык, тип проекта, архитектура, подходы
и паттерны; описание профиля и пример — в [`README.md`](../README.md).

---

## Состояние репозитория

Кода приложения в репозитории нет. Собрано только окружение разработки: свод правил в `rules/`,
`Makefile` подготовки, конфигурация Docker Compose, инструменты в `tools/` и каркас OpenSpec.

Отсюда следует главное для агента: [`rules/clean-architecture.md`](../rules/clean-architecture.md),
[`rules/cqrs.md`](../rules/cqrs.md) и [`rules/ddd.md`](../rules/ddd.md) задают **норму для
создаваемого кода**, а не описывают существующий — с ними сверяются при проектировании, а не ищут
в репозитории слои и агрегаты, которых пока нет.

> **Внимание:** ни сборки, ни тестов, ни линтера кода в репозитории нет. Единственная
> автоматическая проверка — [`tools/make-lint/check.sh`](../tools/make-lint/check.sh),
> и проверяет она `Makefile`, а не код.

## Окружение агента

Агент работает внутри контейнера сервиса `claude` (compose-профиль `claude`,
[`docker-compose.yml`](../docker-compose.yml)). Существенные следствия:

- рабочее дерево смонтировано в каталог из `PROJECT_DIR` — по умолчанию `/app`;
- в контейнере нет ни `make`, ни `docker`: цели окружения выполняются на хосте;
- `.env` внутри контейнера подменён на `/dev/null` — значения приходят через `env_file`,
  читать файл бессмысленно, шаблон переменных лежит в [`.env.example`](../.env.example);
- каталог аккаунта задаёт `CLAUDE_PROFILE`, чужие профили скрыты анонимным томом.

## Команды

### Из контейнера агента

Цели `make` выполняются на хосте через раннер — [`tools/host-runner/call.sh`](../tools/host-runner/call.sh):

```bash
tools/host-runner/call.sh help
tools/host-runner/call.sh init
tools/host-runner/call.sh openspec-init
```

Белый список целей задан в [`runner.py`](../tools/host-runner/runner.py) константой
`ALLOWED_TARGETS`; любое имя вне списка отклоняется кодом `400`. Раннер должен быть запущен
на хосте, иначе вызов вернёт недоступность. Подробности —
[`tools/host-runner/README.md`](../tools/host-runner/README.md).

Проверка объёма секций `Makefile` выполняется в контейнере напрямую:

```bash
sh tools/make-lint/check.sh
```

Прогон обязателен после любой правки `Makefile`
([MAKE-004](../rules/makefile-rules.md#локальный-прогон-проверки-make-004)). Коды возврата:
`0` — норма соблюдена, `1` — есть секции сверх 30 строк, `2` — ошибка вызова или окружения.

### На хосте

```bash
make help
make init
python3 tools/host-runner/runner.py
CLAUDE_PROFILE=<профиль> docker compose run --rm claude
```

## Процесс изменений

Изменения ведутся по OpenSpec. Skills `openspec-propose`, `openspec-apply-change`,
`openspec-update-change`, `openspec-sync-specs`, `openspec-archive-change` и команды `/opsx:*`
создаёт `openspec init` из образа агента — в поставку kit'а они не входят и обновляются целью
`openspec-init`.

- активные изменения — `openspec/changes/`;
- спецификации — `openspec/specs/`;
- язык артефактов — русский, структурные заголовки OpenSpec и ключевые слова `SHALL`/`MUST`
  остаются английскими ([`openspec/config.yaml`](../openspec/config.yaml)).

> **Внимание:** содержимое каталога `openspec/changes/archive/` не читается никогда —
> [READ-004](../rules/reading-rules.md#запрет-каталогов-read-004).

Код проекта в заголовке коммита — `EXT`, формат `EXT-NNN: описание задачи`
по [GIT-009](../rules/git-rules.md#формат-сообщения-коммита). Номер и описание задачи
подтверждаются до коммита по [GIT-010](../rules/git-rules.md#формат-сообщения-коммита).

## Состав поставки kit'а

Файлы окружения SDD Developer Kit перечислены в `.sdd-kit-manifest.json` вместе с их sha256:
`CLAUDE.md`, `AGENTS.md`, `Makefile`, `docker-compose.yml`, `.env.example`, содержимое `rules/`
и `tools/`.

Правка любого из них расходится с поставкой: при переустановке kit'а расхождение придётся
разрешать вручную. Изменение этих файлов — осознанное решение, а не побочный шаг задачи. Файлы
самого проекта — `README.md`, `LICENSE`, этот документ, будущий код — манифестом не покрыты.

### Действующее расхождение с поставкой

Change `bootstrap-extruder-cli` (этап 0–1 [карты плана](./project-plan.md#карта-changeей))
осознанно правит четыре файла поставки: тулчейна целевого языка в контейнере агента нет, и без них
критерий готовности этапа — «сборка и линтер чисты» — проверить нечем.

| Файл поставки | Что добавлено | Зачем |
|---------------|---------------|-------|
| `docker-compose.yml` | сервис `extruder-build` с тулчейном Go, сеть `extruder-net` | единственный способ получить `go` и линтер: в контейнере агента их нет |
| `Makefile` | цели `build`, `lint`, `test` и переменная их вызова | точка входа сборки, проверки и тестов |
| `tools/host-runner/runner.py` | `build`, `lint`, `test` в `ALLOWED_TARGETS` | без них агент не может вызвать новые цели из контейнера |
| `.env.example` | `EXTRUDER_BUILD_IMAGE`, `EXTRUDER_BUILD_IMAGE_TAG` | версия тулчейна закреплена тегом образа |

При переустановке kit'а эти четыре файла придётся сводить вручную: правка в них — проектная,
а не поставочная. Сервис `claude` и остальное содержимое файлов не трогалось.

> **Внимание:** `ALLOWED_TARGETS` читается при импорте модуля. После правки `runner.py`
> запущенный на хосте раннер нужно перезапустить, иначе новые цели он отклонит кодом `400`.

`CLAUDE.md` и `AGENTS.md` — две точки входа с одинаковым перечнем подключаемых документов:
правка перечня вносится в оба файла сразу, иначе агент, читающий только один из них, получит
другой свод.
